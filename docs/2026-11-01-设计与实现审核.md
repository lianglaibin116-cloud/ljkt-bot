## 结论与范围

当前产品已经具备独立 Electron 窗口、本机 Next 服务、独立数据目录、流式聊天和原课程核心。作为内部试用版本，基础路线可保留。作为可以稳定完成备课任务的桌面 Bot，应用层仍有明显缺口：对话、附件、制作任务、课程、编辑和导出成果缺少统一关联及可恢复执行记录。聊天工具目前主要负责准备任务卡、列出课程和打开页面，尚不能在聊天中闭环完成编辑、资料生成或导出。

本轮确认 14 项问题：7 项 P1、7 项 P2。P1 表示可导致能力失真、资料丢失、任务中断或主要流程不可达，建议优先处理；P2 表示影响持续使用、诊断、恢复、维护或正式发布。未发现足以依据现有证据定为 P0 的问题。

范围覆盖 Bot 专属模块、桌面主进程与 preload、本机服务、任务交接、生成页与课堂连接点、附件存储、模型接入、独立 HTML 导出、离线播放器策略和现有 Bot 测试。继承的课件编辑、PBL、媒体、存储等模块检查了相关关键调用链，没有逐行审核全部上游源码。结论不等同于所有模型、所有互动和所有操作系统的完整验收。

- 用户要求：Bot 与原系统独立；保留原能力；采用聊天式桌面入口；返回对话不进入网页首页；成果可导出并定位。

## 已有设计中可以继续保留的部分

1. Electron 与课程核心分离，服务绑定 127.0.0.1，采用独立端口和 userData，独立项目默认不加载原 OpenMAIC 源码。
2. 主窗口开启 contextIsolation、sandbox、webSecurity，关闭 Node integration；preload 只提供有限接口。主进程 IPC 校验可信来源和主 frame。这些边界应保留。
3. 复用原模型解析、专业编辑、课程资料及渲染模块，比重新实现这些核心能力更适合当前阶段。
4. Bot 的返回消息检查 origin 和 source；制作会话已有单独 session key，避免旧 frame 清理新任务。
5. 聊天已有取消、部分回复保留和本机历史恢复。现有 Bot 单元测试可以作为后续补齐的基础。

## 主要问题

### F01 · P1 · HTML 允许缺失资源的文件落盘，但播放器禁止访问远程资源

**要求**：独立 HTML 能携带课程所需资源，并说明无法携带的能力。  
**实现**：导出先 saveAs，再根据 inlineFailures/unresolvedMedia 数量发警告。资源内联失败时原地址保留；导出 HTML 的 CSP 同时禁止 https 脚本、图片、字体和所有 connect 请求，互动 srcdoc frame 继承该限制。因此资源缺失会形成一个已知不完整的文件，即使联网，也不能依靠原远程地址补加载。

**影响**：出现“文件已经导出”但互动空白、编译器不可用、局部显示缺失。“9 个资源失败”不能只理解为网络重试提示。
**修正**：增加导出前兼容检查，逐场景列出失败 URL、资源类型、具体原因和受影响能力。完整离线导出必须通过必需依赖检查；部分导出应成为用户明确选择，并在文件内保存兼容报告。不要为绕过缺失资源而直接放开 CSP。

证据：[先保存再警告](/Users/sy/ljkt-bot/lib/export/use-export-html.ts:106)、[失败保留 script 地址](/Users/sy/ljkt-bot/lib/export/inline-assets.ts:668)、[离线 CSP](/Users/sy/ljkt-bot/lib/export/standalone-html/assemble.ts:54)。

**更正前面的判断**：此前主要归因于代理、并认为保留远程 URL 后联网可能可用，解释不完整。该导出文件的 CSP 是另一个确定性限制。

### F02 · P1 · 默认把真实 C++ 活动替换成固定检查器，且存在错误通过

**要求**：保留编程互动的真实能力，兼容性变化应明确。  
**实现**：HTML 导出默认打开 offlineCppExercises，按依赖字符串及标题识别 Hello World/成绩统计页面，然后替换整个活动。检查器使用正则寻找代码片段；成绩结果由 JavaScript 固定公式计算，没有执行学生编辑后的 C++。

**隔离复现**：
- if(false) 中的 cout 被输出并判为通过，真实程序应不产生输出。
- 只有注释、没有可链接 main 的文本被判为通过。
- 成绩页检查关键字后使用固定求平均公式，不能验证任意代码的实际含义。

页面虽然写了“不是完整编译”，这种默认替换仍会改变原课件的教学语义，不能视为已完成编译器兼容修复。这是我上次接入的改动，应列入优先纠正项。

**修正**：撤销默认自动替换，把“示例检查版”作为明确选择的独立导出选项。真实编译走受支持的运行时适配器，完整处理 Worker、WASM、文件、初始化和执行约束；不支持的活动应准确显示兼容状态。离线检查器若保留，必须限制可接受输入并拒绝不能判断的程序，不能据正则片段推导程序执行结果。

证据：[默认开启](/Users/sy/ljkt-bot/lib/export/standalone-html/build-standalone-html.ts:645)、[导出内容替换](/Users/sy/ljkt-bot/lib/export/use-export-classroom.ts:244)、[字符串识别](/Users/sy/ljkt-bot/lib/interactive/offline-cpp-fallback.ts:259)、[Hello World 正则](/Users/sy/ljkt-bot/lib/interactive/offline-cpp-fallback.ts:115)、[固定平均分计算](/Users/sy/ljkt-bot/lib/interactive/offline-cpp-fallback.ts:186)。

### F03 · P1 · 历史对话里的材料会被 24 小时临时清理误删

**要求**：聊天恢复后，历史材料及任务卡仍可使用。  
**实现**：Bot 上传材料调用 storeDocumentBlob，它实际写入临时 imageFiles 表；历史消息只保存 storageKey。生成预览页每次进入都会调用 cleanupOldImages(24)，直接按 createdAt 删除该表记录，不核对仍被对话或任务引用的文档。

**隔离复现**：内存数据库存入一份材料，设为 25 小时前，清理前可读取，执行真实 cleanupOldImages 后读取为 null。没有访问用户数据库。

**影响**：第二天从历史卡片重新制作时，附件名称还在，但原文件已不存在。
**修正**：独立材料表/资源仓库，稳定 materialId、引用关系、内容 hash 和状态；只有无引用的临时资源才按期限清理。迁移现存附件引用，材料失效时允许定位原文件重新关联。

证据：[材料上传](/Users/sy/ljkt-bot/components/bot/BotWorkspace.tsx:373)、[文档写入临时表](/Users/sy/ljkt-bot/lib/utils/image-storage.ts:185)、[清理所有旧记录](/Users/sy/ljkt-bot/lib/utils/image-storage.ts:163)、[生成页触发清理](/Users/sy/ljkt-bot/app/generation-preview/page.tsx:225)。

### F04 · P1 · 会话切换没有隔离课程上下文和右侧工作区

**要求**：每个教学对话使用自己的课程、附件和工作状态。  
**实现**：selectedCourse、workspace 是组件全局 state；newChat 只更新 thread、draft、error、materials，没有重置或恢复课程、工作区。BotThread 也没有这些关联字段。下一次 send 会自动读取 selectedCourse 对应课程内容。

**复现路径**：对话 A 关联课程 A → 新建或切换对话 B → 直接提问；请求仍携带课程 A 正文。A 的工作区仍可能展示在 B 的对话旁。
**影响**：模型基于不相关课件回答，后续操作容易错位，用户无法凭对话判断当前作用对象。
**修正**：以 threadId/projectId 保存课程关联和工作区状态；切换时恢复或清空。可见显示当前课程与版本，每个工具请求显式携带上下文绑定。

证据：[全局选择状态](/Users/sy/ljkt-bot/components/bot/BotWorkspace.tsx:82)、[发送时注入课程](/Users/sy/ljkt-bot/components/bot/BotWorkspace.tsx:239)、[会话切换](/Users/sy/ljkt-bot/components/bot/BotWorkspace.tsx:393)、[会话结构](/Users/sy/ljkt-bot/lib/bot/contracts.ts:31)。

### F05 · P1 · 制作卡没有执行状态、去重和成果关联

**要求**：老师能区分待执行、生成中、成功、失败，并从对话找回成果。  
**实现**：BotAction 只有输入参数；每次点击制作卡都 nanoid() 新建 session。按钮在执行后仍可点击，没有幂等键，也不保存 taskId/courseId/result。frame 返回 ready 的数据只包含 courseId，没有原 thread/action 身份或制作完成事件。

**影响**：重复点击可启动重复制作并产生重复模型请求；生成成功后卡片仍是“开始整理大纲”；聊天没有可核实的任务结果，不能准确跟进后续操作。
**修正**：持久 Task，关联 threadId/actionId/courseId，执行去重，记录状态、进度、失败原因和产物；事件回传必须带任务身份，任务卡展示实际结果。

证据：[Action 结构](/Users/sy/ljkt-bot/lib/bot/contracts.ts:10)、[每次新建会话](/Users/sy/ljkt-bot/components/bot/BotWorkspace.tsx:322)、[无执行禁用的卡片](/Users/sy/ljkt-bot/components/bot/BotWorkspace.tsx:701)、[仅 ready 通知](/Users/sy/ljkt-bot/components/bot/BotFrameBridge.tsx:25)。

### F06 · P1 · 制作生命周期绑定 iframe，草稿与恢复缺少持久任务入口

**要求**：较长制作任务应能在用户切换视图后继续，或准确取消并可恢复。  
**实现**：关闭工作区、新开制作卡会卸载/替换 iframe；生成预览页卸载时 abort。前期制作资料保存在 sessionStorage，Bot 不记录 sessionId，也没有恢复任务列表。进入课堂后的部分恢复能力已有，但前期审阅草稿与完整任务链没有 Bot 级持久记录。generationParams 仍是共享的单一 sessionStorage key，缺少 courseId/taskId 绑定。

**影响**：关闭视图就中断前期生成；重开卡片另起任务；应用完全退出后无法从 Bot 列表恢复尚未生成课程的大纲。
**修正**：任务状态交给本机服务和持久存储，UI 订阅进度；视图关闭与取消任务分开。保留已有课程恢复逻辑，给前期解析/大纲/确认/生成也增加持久检查点。generationParams 按任务和课程存取。

证据：[关闭工作区](/Users/sy/ljkt-bot/components/bot/BotWorkspace.tsx:857)、[frame key](/Users/sy/ljkt-bot/components/bot/BotWorkspace.tsx:869)、[卸载 abort](/Users/sy/ljkt-bot/app/generation-preview/page.tsx:252)、[sessionStorage](/Users/sy/ljkt-bot/components/bot/BotWorkspace.tsx:338)、[共享 generationParams](/Users/sy/ljkt-bot/app/generation-preview/page.tsx:1034)、[课堂恢复参数](/Users/sy/ljkt-bot/components/classroom/ClassroomSurface.tsx:350)。

### F12 · P2 · 缺少统一网络策略和可操作的诊断，错误被泛化

课程资源代理在 Node 服务使用经过校验的直连 dispatcher；Electron 页面资源另有 Chromium 网络环境；模型配置又有自身 transport。桌面主进程未提供统一代理配置和两条网络路径的诊断。Bot API 的 catch 将多种故障归并为“检查模型配置或网络”，也没有记录可对应用户报告的请求编号。

修正：建立桌面网络设置，分别检测模型 API、本机资源代理与页面运行时资源。按认证、额度、限流、DNS、代理、TLS、超时、模板/资源缺失等返回脱敏错误代码和可重试状态。提供诊断报告、日志轮转、显式的本地模型授权范围。保留 SSRF 和证书校验，不能用全局放开网络限制处理。

### F13 · P2 · 部分验收代码仍绑定旧首页，当前“通过记录”不能代表新流程

现有 Bot 单元测试本轮 14 项通过。抽查 2 项浏览器回归：滚动测试通过；“制作卡进入大纲”测试失败，原因是仍寻找已移除的“课件工作台”按钮及旧 iframe 标题。桌面 smoke 脚本也仍期待该按钮打开网页教师首页。这与当前 Bot 不出现网页首页的目标冲突。

修正：以当前用户流程维护验收；覆盖解析材料→任务确认→大纲→生成→编辑→保存→导出→实际打开文件，以及切换会话、关闭工作区、断网、退出重启。真实模型验收可小规模、明确预算执行；固定模拟测试继续保留。将“构建通过”“mock 测试通过”“真实离线成果可用”分别记录。

证据：[失效浏览器选择器](/Users/sy/ljkt-bot/e2e/bot/interface-regressions.spec.ts:184)、[桌面 smoke 旧假设](/Users/sy/ljkt-bot/desktop/main.cjs:305)、[旧验收边界说明](/Users/sy/ljkt-bot/docs/本次构建与验证.md:16)。

### F14 · P2 · 本机 HTTP 信任边界缺少固定 Host 与桌面会话凭证

服务绑定 loopback 是正确措施，但没有形成桌面应用专有的 API 会话认证。ACCESS_CODE 未设置时全局 gate 放行。Bot chat 的 origin 检查将客户端 Host 头当作可信目标；未核对其是否为受认可的 loopback host。

本轮无敏感数据探测：以 Host: audit.invalid、Origin: http://audit.invalid 请求运行中本机服务，health 返回 200，空聊天体返回 400 参数错误而非 403 来源拒绝。证明任意 Host 进入了应用参数层；未执行 DNS 重绑定攻击，也未证明用户数据外泄。风险取决于浏览器本地网络访问策略、部署配置及具体 API。

修正：统一 Host/Origin allowlist 与每次桌面启动的应用会话认证，覆盖所有本机 API；明确 iframe 的受信 UI 与不受信互动内容边界。正式发行前验证 DNS 重绑定、跨站写请求和同机应用访问策略。

证据：[loopback 绑定](/Users/sy/ljkt-bot/desktop/service.cjs:29)、[可选访问码](/Users/sy/ljkt-bot/proxy.ts:20)、[Host 比较](/Users/sy/ljkt-bot/app/api/bot/chat/route.ts:15)。

## 建议的整体架构

当前主要关系：

~~~mermaid
flowchart LR
    A[Bot 对话及临时状态] --> B[任务卡]
    B --> C[同源 iframe]
    C --> D[原课程 UI 与生成逻辑]
    A --> E[独立 threads 数据库]
    C --> F[课程数据库和 sessionStorage]
    D --> G[导出 hook]
    G --> H[Electron 下载事件]
~~~

建议保留现有课程渲染与专业编辑，补齐应用服务和统一数据对象：

~~~mermaid
flowchart TB
    UI[Bot 对话 / 课程库 / 任务 / 成果] --> APP[统一应用服务与受限工具]
    FRAME[复用的课程编辑和播放 UI] <--> APP
    APP --> TASK[本机任务编排与持久检查点]
    APP --> MAT[材料解析与来源检索]
    APP --> COURSE[课程读取 / 修改 / 版本 / 资料]
    APP --> EXPORT[兼容性预检 / 导出 / 成果记录]
    APP --> MODEL[模型与网络接入]
    TASK --> DB[统一关联存储]
    MAT --> DB
    COURSE --> DB
    EXPORT --> DB
    DESKTOP[Electron 主进程] --> OS[文件系统 / 安全存储 / 下载 / 更新]
    DESKTOP <--> APP
~~~

统一对象至少包括 Project、Thread、Material、Task、CourseRevision、Artifact。任务/事件至少携带 threadId、taskId、courseId、revision 与 requestId，执行结果进入历史，避免仅凭自然语言宣布完成。

本机任务存储可基于现有存储抽象和本地数据库实现，不必为了 Bot 的基础任务能力强制要求外置 PostgreSQL。iframe 可以继续作为 UI 复用手段，业务任务的所有权应由本机应用服务持有。

生成互动需要“运行时能力清单”：Canvas、公式、图表等使用已支持资源；Worker/WASM/编译器活动通过明确适配器；实时 AI/API 活动标注在线条件。资源收集、课堂播放和导出应读取同一份清单，避免让每个 AI 生成页面自行决定任意依赖。

## 修复顺序与验收

1. **先修数据与教学正确性**：F01–F04；停止默认替换真实编程能力；避免清理持久材料；明确每个会话当前课程。验收包含不会执行的代码不得判为执行成功、旧材料仍可读取、跨会话不带错课件。
2. **再补任务和入口**：F05–F08；持久任务、完整课程库、材料正文、生成成果关联。验收包含重复点击不重复收费、关闭 UI 不丢任务、从历史能找回原成果。
3. **再补持续使用能力**：F09–F12；上下文预算、备份恢复、下载中心、网络诊断。验收包含长对话、重启恢复、备份还原和下载取消。
4. **最后建立发布门槛**：F13–F14；更新端到端验收、主机与应用会话边界、密钥安全存储、签名更新与平台验证。
